### Ví dụ chi tiết: UC-01 Đăng nhập
- **Mô tả**: User nhập username + password, hệ thống xác thực và trả về phiên hoặc thông báo lỗi.
- **Tiên quyết**: User có tài khoản đang hoạt động.
- **Luồng chính**:
  1. User nhập username, password.
  2. Hệ thống kiểm tra tài khoản tồn tại, đang active, không bị khóa.
  3. Hệ thống xác minh mật khẩu (hash compare).
  4. Dù thành công/thất bại → tạo `LoginEvent`.
  5. Chuyển `LoginEvent` cho Rule Engine → Rule Score.
  6. Chuyển `LoginEvent` cho ML Engine → Anomaly Score.
  7. Risk Engine tính Total Risk Score & Risk Level.
  8. **LOW** → tạo session, trả token.
- **Luồng thay thế**:
  - 4a. Sai mật khẩu → tăng biến đếm thất bại, kiểm tra lockout.
  - 7a. **MEDIUM/HIGH** → UC-02 (yêu cầu MFA).
  - 7b. **CRITICAL** → UC-25 (tạo alert) + từ chối đăng nhập.
- **Yêu cầu đặc biệt**: hash mật khẩu = Argon2id; không log plaintext password; rate limit 5 lần/phút/IP.

## 5. Sơ đồ lớp — đề xuất

### Class diagram chính (chia theo 3 module)

**core-app module (Sony)**
- `User` — id, username, email, passwordHash, status (ACTIVE/LOCKED), role, createdAt
- `Role` — id, name (USER/SOC_ANALYST/SECURITY_ADMIN/SECURITY_MANAGER)
- `UserRole` — userId, roleId (bảng nối)
- `TrustedDevice` — id, userId, deviceId, fingerprint, trustLevel, addedAt
- `Session` — id, userId, token, ip, deviceId, createdAt, expiresAt, revokedAt
- `MfaChallenge` — id, userId, sessionId, method (TOTP/SMS), codeHash, expiresAt, status
- `AuthPolicy` — id, name, passwordMinLen, mfaRequired, lockoutThreshold, sessionTtl

**detection-engine module (Tuấn Anh)**
- `LoginEvent` — id, userId, timestamp, success, sourceIp, deviceId, userAgent, region, mfaUsed, failureReason
- `Rule` — id, code (RULE-001..006), name, description, weight, threshold, enabled
- `RuleHit` — id, loginEventId, ruleId, ruleScore, hitAt
- `RiskScore` — id, loginEventId, ruleScore, anomalyScore (normalized), totalRiskScore, riskLevel (LOW/MEDIUM/HIGH/CRITICAL), computedAt
- `Alert` — id, loginEventId, level, status (NEW/ACK/INVESTIGATING/RESOLVED/CLOSED), assignedTo, createdAt
- `Incident` — id, alertId, status, classification (TRUE_POSITIVE/FALSE_POSITIVE/NEEDS_WATCH), notes, closedAt
- `AuditLog` — id, actorId, action, resource, beforeState, afterState, timestamp

**ml-service module (Khang)**
- `FeatureVector` — userId, hourOfDay, failCountWindow, ipChangeRate, newDeviceFlag, avgTimeBetweenLogins, deviationScore, …
- `AnomalyScore` — loginEventId, rawScore, normalizedScore (0-1), isAnomaly, modelVersion, modelType (IsolationForest), reasonCodes
- `ModelVersion` — id, version, trainedAt, metricsJson, status (ACTIVE/RETIRED)

### Quan hệ chính
- `User 1—* LoginEvent`
- `User 1—* Session`
- `LoginEvent 1—1 RiskScore`
- `LoginEvent 1—* RuleHit *—1 Rule`
- `LoginEvent 1—1 AnomalyScore`
- `RiskScore 1—1 Alert`
- `Alert 1—1 Incident`
- `User 1—* TrustedDevice`
- `User *—* Role` (qua UserRole)
- `AuditLog *—1 User` (actor)

## 6. Biểu đồ tuần tự — đề xuất

### ST-01: Luồng đăng nhập + đánh giá rủi ro + cảnh báo

```
User → AuthController → AuthenticationService → LoginEventStore
    → RuleEngine → RiskEngine
    → MLService → RiskEngine
    → PolicyEngine → AuthController
    → AlertEngine → NotificationChannel → SOCAnalyst
```

Các sequence diagram cần vẽ (≥ 4 biểu đồ):
1. **ST-01**: Đăng nhập thành công (rủi ro LOW) — happy path.
2. **ST-02**: Đăng nhập có MFA — rủi ro MEDIUM/HIGH.
3. **ST-03**: Đăng nhập bất thường — CRITICAL → tạo alert.
4. **ST-04**: SOC Analyst xử lý alert → đóng incident.
5. **ST-05**: Security Admin cấu hình Rule/threshold.
